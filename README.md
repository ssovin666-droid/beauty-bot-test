# Beauty Bot — Phase 1

Это тестовая версия Telegram-бота для первой рекламной кампании.

## Что он делает

Бот:

1. Регистрирует пользователя при `/start`.
2. Сохраняет доступные Telegram-поля пользователя:
   - Telegram ID;
   - username;
   - имя;
   - фамилию;
   - language_code;
   - is_premium, если Telegram его передал.
3. Сохраняет источник перехода из ссылки `?start=...`.
4. Сохраняет **каждый повторный Start**, поэтому не теряются повторные рекламные касания.
5. Позволяет добавлять товары в:
   - 📦 Полку;
   - ✨ Вишлист.
6. Фиксирует события воронки:
   - `start`;
   - `open_polka`;
   - `open_wishlist`;
   - `add_item_click`;
   - `item_added`;
   - `notifications_on`;
   - `notifications_off`;
   - `activated`.
7. Считает пользователя активированным, если:
   - он добавил минимум `ITEMS_THRESHOLD` уникальных товаров;
   - и включил уведомления.
8. Администратор может:
   - получить краткий отчёт командой `/stats`;
   - выгрузить всю базу в CSV командой `/export`.

## Что Phase 1 НЕ делает

Он пока не:
- ищет товары по магазинам;
- получает реальные цены;
- отслеживает изменение цены;
- отправляет реальные уведомления о скидках.

Это сознательно: сначала проверяется спрос и поведение пользователей.

# Часть 2. Создать Telegram-бота

## Шаг 1. Открыть BotFather

В Telegram найди:

```text
@BotFather
```

Важно: проверь, что это официальный BotFather.

## Шаг 2. Создать нового бота

Напиши:

```text
/newbot
```

BotFather сначала попросит отображаемое имя.

Например:

```text
Beauty Wishlist
```

Потом попросит username. Он должен заканчиваться на `bot`.

Например:

```text
beauty_wishlist_test_bot
```

Если username занят, придумай другой.

## Шаг 3. Скопировать токен

BotFather пришлёт строку примерно такого вида:

```text
1234567890:AAExampleVeryLongSecretToken
```

Это `BOT_TOKEN`.

### Важно

Токен — пароль от бота.

Нельзя:
- отправлять его клиентам;
- публиковать в GitHub;
- вставлять в README;
- показывать на скриншотах.

Если токен случайно опубликован, его нужно перевыпустить через BotFather.

# Часть 3. Первый запуск на своём компьютере

Этот шаг нужен, чтобы проверить, что бот работает, до размещения на сервере.

## Шаг 1. Установить Python

Нужен Python 3.10 или новее.

Проверка:

```bash
python --version
```

или:

```bash
python3 --version
```

## Шаг 2. Распаковать папку

Распакуй ZIP с проектом.

Открой Terminal / Командную строку именно в папке:

```text
beauty_bot_phase1
```

## Шаг 3. Создать виртуальное окружение

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Windows

```bat
python -m venv .venv
.venv\Scripts\activate
```

## Шаг 4. Установить зависимости

```bash
pip install -r requirements.txt
```

## Шаг 5. Создать `.env`

В папке уже есть:

```text
.env.example
```

Сделай его копию и назови:

```text
.env
```

В `.env` вставь токен:

```text
BOT_TOKEN=ТВОЙ_ТОКЕН
ADMIN_IDS=
DB_PATH=beauty_bot.db
ITEMS_THRESHOLD=2
```

## Шаг 6. Запустить

```bash
python bot.py
```

Если всё нормально, в терминале появится сообщение:

```text
Beauty Bot Phase 1 запущен
```

Не закрывай Terminal, пока проверяешь локально.

# Часть 4. Проверить бота

## Проверка 1. Обычный Start

Открой своего бота в Telegram и нажми Start.

Должно появиться:
- описание;
- Полка;
- Вишлист;
- кнопка уведомлений.

## Проверка 2. Узнать свой Telegram ID

Отправь боту:

```text
/id
```

Он ответит, например:

```text
Твой Telegram ID: 123456789
```

Скопируй число.

Останови бота комбинацией:

```text
Ctrl + C
```

Открой `.env` и вставь ID:

```text
ADMIN_IDS=123456789
```

Снова запусти:

```bash
python bot.py
```

Теперь только этот Telegram-аккаунт сможет пользоваться `/stats` и `/export`.

## Проверка 3. Тестовая рекламная ссылка

Допустим username бота:

```text
beauty_wishlist_test_bot
```

Открой ссылку:

```text
https://t.me/beauty_wishlist_test_bot?start=test_campaign_01
```

Нажми Start.

Бот сохранит:

```text
test_campaign_01
```

как источник перехода.

Официальный Telegram deep-link имеет формат:

```text
https://t.me/BOT_USERNAME?start=PARAMETER
```

Для параметра безопасно использовать:
- латинские буквы;
- цифры;
- `_`;
- `-`.

В проекте параметр ограничивается 64 символами.

## Проверка 4. Воронка

1. Нажми «Вишлист».
2. Нажми «Добавить товар».
3. Напиши:
   ```text
   Dior Lip Glow
   ```
4. Добавь ещё один товар.
5. Включи уведомления.

После двух уникальных товаров + уведомлений пользователь станет `activated`.

# Часть 5. Проверить статистику

## Быстро в Telegram

Администратор отправляет:

```text
/stats
```

Бот покажет:
- регистрации;
- сколько людей добавили хотя бы один товар;
- сколько включили уведомления;
- сколько активировались;
- Start → Activation;
- разбивку по первому источнику.

## Полная выгрузка

Отправь:

```text
/export
```

Бот пришлёт ZIP.

Внутри:

```text
users.csv
starts.csv
items.csv
events.csv
```

### users.csv

Один пользователь = одна строка.

Главные поля:

```text
user_id
username
first_name
last_name
first_source
last_source
started_at
last_started_at
notifications
activated_at
```

### starts.csv

Каждое нажатие Start.

Поэтому один пользователь может быть там несколько раз.

Главные поля:

```text
user_id
source
started_at
```

### items.csv

Все товары, добавленные в Полку или Вишлист.

### events.csv

Все ключевые действия пользователя.

Это самая подробная таблица для анализа воронки.

# Часть 6. Как читать first_source и last_source

Представим:

### 10 сентября

Анна пришла по ссылке:

```text
?start=wish_01
```

Получим:

```text
first_source = wish_01
last_source  = wish_01
```

### 13 сентября

Она снова увидела другое объявление и нажала:

```text
?start=polka_03
```

Теперь:

```text
first_source = wish_01
last_source  = polka_03
```

А в `starts.csv` будут обе записи.

Поэтому позднее мы сможем отдельно анализировать:
- первый источник привлечения;
- последнее рекламное касание;
- все касания пользователя.

# Часть 7. Разместить бота на Railway

Локально бот работает только пока открыт компьютер.

Для рекламы нужен сервер, который работает постоянно.

Ниже инструкция для Railway.

## Шаг 1. Создать GitHub-репозиторий

Зайди в GitHub и создай новый приватный репозиторий.

Например:

```text
beauty-bot-phase1
```

Загрузи туда:

```text
bot.py
stats.py
requirements.txt
.env.example
.gitignore
README.md
```

### НЕ загружай

```text
.env
beauty_bot.db
```

`.gitignore` уже настроен, чтобы эти файлы не попадали в Git.

---

## Шаг 2. Создать проект Railway

1. Открой Railway.
2. Создай новый проект.
3. Выбери развёртывание из GitHub repository.
4. Выбери репозиторий `beauty-bot-phase1`.

Railway должен определить Python-проект по `requirements.txt`.

---

## Шаг 3. Добавить переменные

Открой у сервиса вкладку:

```text
Variables
```

Добавь:

```text
BOT_TOKEN=токен_от_BotFather
ADMIN_IDS=твой_Telegram_ID
ITEMS_THRESHOLD=2
DB_PATH=/data/beauty_bot.db
```

Токен не нужно сохранять в GitHub.

---

## Шаг 4. Подключить постоянное хранилище

Это обязательный шаг.

Без Volume база SQLite может находиться во временной файловой системе сервиса и потеряться при новом deployment.

В Railway создай Volume и подключи его к сервису.

Mount path:

```text
/data
```

После этого:

```text
DB_PATH=/data/beauty_bot.db
```

будет хранить базу внутри Volume.

---

## Шаг 5. Команда запуска

В настройках Deploy / Start Command укажи:

```text
python bot.py
```

Сделай deployment.

---

## Шаг 6. Проверить Logs

Открой Logs.

Ищи:

```text
Beauty Bot Phase 1 запущен
```

Если оно появилось и нет красной ошибки — бот работает.

# Часть 8. Финальный тест перед рекламой

Пройти этот список полностью.

## Telegram

- [ ] `/start` работает.
- [ ] Полка открывается.
- [ ] Вишлист открывается.
- [ ] Товар добавляется.
- [ ] Повторный одинаковый товар не создаёт дубль.
- [ ] Уведомления включаются и выключаются.
- [ ] `/id` показывает Telegram ID.

## Администратор

- [ ] `ADMIN_IDS` установлен.
- [ ] `/stats` работает у администратора.
- [ ] `/stats` не работает у обычного пользователя.
- [ ] `/export` присылает ZIP.

## Атрибуция

Проверить минимум две разные ссылки:

```text
https://t.me/BOT_USERNAME?start=test_a
```

и:

```text
https://t.me/BOT_USERNAME?start=test_b
```

Зайти с разных Telegram-аккаунтов или попросить двух людей пройти тест.

После этого открыть `/stats` и `/export`.

В отчёте должны существовать отдельно:

```text
test_a
test_b
```

# Часть 9. Что мы сделаем потом для Яндекс Директа

До запуска Яндекс Директа код переписывать заново не нужно.

Точка интеграции уже существует:

```text
?start=...
```

Следующим этапом мы определим:
1. какие именно гипотезы тестируем;
2. какие кампании и группы будут в Яндекс Директе;
3. как кодировать campaign / audience / creative в `start`;
4. какие динамические параметры Яндекс может передавать;
5. как сопоставить расход рекламы с регистрациями и активациями.

Главное: текущая база уже умеет сохранять источник каждого Start.

# Команды бота

```text
/start       — старт
/id          — показать свой Telegram ID
/privacy     — какие данные хранит тестовая версия
/stats       — статистика, только администратору
/export      — CSV-экспорт, только администратору
```

# Важные ограничения Phase 1

1. FSM хранится в памяти. Если сервер перезапустится ровно между «Добавить товар» и ответом пользователя, бот забудет, что ждал название. Для первого теста это допустимо.
2. SQLite подходит для небольшой тестовой кампании. При росте продукта базу лучше перенести на PostgreSQL.
3. `username` у Telegram-пользователя может отсутствовать.
4. Telegram не передаёт боту автоматически телефон или email.
5. Реальные скидки в этой версии не отслеживаются.

# Если что-то не работает

Сначала проверить:

1. Правильно ли вставлен `BOT_TOKEN`.
2. Нет ли пробелов или кавычек вокруг токена.
3. Запущен ли процесс `python bot.py`.
4. На Railway — открыт ли Logs и нет ли ошибки.
5. Подключён ли Volume к `/data`.
6. `DB_PATH` равен `/data/beauty_bot.db`.
7. Telegram ID администратора действительно указан в `ADMIN_IDS`.

Не публикуй BOT_TOKEN при диагностике. Если понадобится помощь, достаточно прислать текст ошибки из Logs без токена.
